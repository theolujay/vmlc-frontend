# QR-Based Security for Final Exams (Frontend Implementation)

## Overarching Idea
To ensure that only physically present candidates can attempt the Final Exams, a real-time QR code verification layer will be implemented. When a candidate attempts to start or resume a final exam, they must present a QR code generated by their dashboard to an Admin. Once scanned and verified by the Admin, the candidate's exam session is "unlocked" in real-time via WebSockets, allowing them to proceed.

## 1. Candidate Dashboard Implementation

### Workflow:
- **Detection**: The system identifies a "Final" exam based on the `stage` property (e.g., `exam.stage.toLowerCase() === 'final'`) or `delivery_mode === 'in_person'`.
- **Primary Action**: In `PrimaryAction.tsx`, when a candidate clicks "START EXAM" or "RESUME EXAM" for a final exam:
    - Instead of navigating directly to the exam page, a **QR Modal** is displayed.
    - The modal contains a QR code representing the candidate's attempt (encoded: `candidateId:examId:timestamp`).
    - The UI displays a "Waiting for Admin Verification..." status with a loading spinner.
- **WebSocket Listener**:
    - The component uses the `useSocket` hook to listen for a specific event: `exam.unlocked`.
    - When the event is received, the modal closes, and the candidate is automatically redirected to the exam interface (`/exam-portal/${examId}/exam`).

### Components Needed:
- `QRVerificationModal`: Displays the QR code and status.
- `qrcode.react`: Library to generate the QR code on the fly.

---

## 2. Admin Dashboard Implementation

### Workflow:
- **Scanner Access**: In the "Exams & Questions" tab (`ExamSection.tsx`), a "Scan QR" button will be added to the `AdminHeader`.
- **Visibility**: This button is only visible to users with `ADMIN` role (or higher) and only when there is an ongoing final exam session.
- **Scanning**:
    - Clicking the button opens a `ScannerModal` using the device's camera.
    - Upon a successful scan, the Admin's frontend sends a WebSocket action (or API request) to the backend: `unlock_exam`.
    - Payload: `{ candidateId, examId }` (extracted from the QR).
- **Feedback**: Displays a success toast once the backend confirms the unlock signal has been broadcast.

### Components Needed:
- `AdminQRScannerModal`: Integrates the camera for scanning.
- `html5-qrcode`: Library for high-performance QR code scanning.

---

## 3. Real-time Integration
- **Socket Action**: Use the existing `UnifiedConsumer` infrastructure.
- **New Event Types**:
    - `exam.unlock_request`: Sent by Admin to backend.
    - `exam.unlocked`: Broadcast by backend to the specific candidate's WebSocket group.

## 4. Dependencies to Add
```bash
# For QR Generation (Candidate side)
npm install qrcode.react

# For QR Scanning (Admin side)
npm install html5-qrcode
```

## 5. Security & UX Considerations
- **Visual Feedback**: Ensure the candidate knows exactly why they are waiting (i.e., "Please show this QR to the invigilator").
- **Real-time**: WebSocket ensures zero-latency between scan and unlock, preventing candidate frustration.
- **Blocking**: Ensure the manual URL navigation to the exam page is also blocked on the frontend if the "unlocked" state hasn't been verified (via a HOC or route guard).
